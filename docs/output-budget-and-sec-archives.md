# Output budget and SEC archive check

Date: 2026-11-11. Source status matters: the model outputs below are operator-observed; server behavior is from vendor documentation; SEC archive availability was directly checked. None is a claim of model accuracy.

## What the six local runs tell us

At the time of the six operator runs, `RAG_LLM_MAX_TOKENS` was **2,048 generated tokens**. This is a ceiling for the *output*, not the server's total context window. In A, B and F, the server reported **1,129**, **1,228**, and **854** generated tokens, respectively. In C, D and E the first call reported **2,048 exactly**. D's structured output failed to parse. Those logs are consistent with a too-small output budget, but the prior client discarded `finish_reason` and cannot prove why C/E abstained. The second short model call came from the existing fallback verification path, not a retry that completed the original answer.

There is no universal recommended number of output tokens for an SEC RAG answer. For this *sample*, 2,048 sufficed for three short quote-matched responses; 2,048 was exhausted for three broad fiscal-year requests. At the operator's request the **current default and local override are now 4,096** without a controlled model run. Prompt and generation must still fit the server's effective **per-slot context**. For example, the observed prompts were about 3,286–4,561 tokens before generation; 4,561 + 4,096 = 8,657, beyond an 8,192-token context even before other overhead. The client will expose length-limited completions, but a request that the server rejects for exceeding context is a different error. Narrow a multi-period question or use fewer passages if that happens. A larger output cap does not establish better answer quality.

The [llama.cpp server API](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md) documents prompt/completion usage and per-slot context. The [OpenAI Python client](https://github.com/openai/openai-python/blob/main/src/openai/lib/_parsing/_completions.py) treats `finish_reason=length` as incomplete when parsing. In [llama.cpp issue #30773](https://github.com/ggml-org/llama.cpp/issues/30773), a community reporter contrasts truncated Responses streaming with Chat Completions, which returns `finish_reason=length`; that is relevant to the **signal**, not proof this app had that upstream issue. [Lost in the Middle (Liu et al.)](https://arxiv.org/abs/2307.03172) finds that more context alone can worsen retrieval use depending on evidence position; it does not prescribe this app's budget.

The local client now refuses to treat `finish_reason=length` as a complete answer for native llama.cpp and OpenAI-compatible Chat Completions. Streamlit displays an explicit output-limit warning, keeps source passages visible, and does not waste a second model call verifying a known-partial answer. Other parse failures remain distinct; no automatic retry was introduced. The output cap was raised to 4,096 at the operator's request; model-dependent confirmation remains pending.

## Historical SEC documents are still accessible

The SEC's own [Accessing EDGAR Data](https://www.sec.gov/search-filings/edgar-search-assistance/accessing-edgar-data) says public EDGAR indexes run back to 1994Q3, documents are in `/Archives/edgar/data/{CIK}/{accession-without-dashes}/`, and requests should respect fair-access limits. The filing indexes for [CMG Q2 2024](https://www.sec.gov/Archives/edgar/data/1058090/000105809024000032/0001058090-24-000032-index.html) and [JNJ Q1 2026](https://www.sec.gov/Archives/edgar/data/200406/000020040626000087/0000200406-26-000087-index.html) were fetched and list the original 10-Q HTML. A missing browser tab or Streamlit result is not evidence that SEC deleted a historical filing. The current Streamlit app holds only the latest result in session state, not a persistent research history; closing/restarting it does not preserve prior answers. Index metadata holds `filing_url` for linked chunks, but the app does not archive its own copies of external SEC pages. Confirm an individual broken link's URL and HTTP status before changing ingestion or claiming missing archive coverage.
