# Evidence system audit

Date: 2026-11-11. Scope: local SEC research prototype, not the landing page's visual design. This is a code and index audit, not a claim that the system has passed a human-reviewed answer evaluation. No runtime policy was changed in this audit.

Follow-up on the same date: the date filter now selects a filing per ticker rather than one global filing date. For newly indexed rows, the builder stores `report_period_end` from the SEC submissions `reportDate` field; retrieval prefers an exact period match when that metadata exists. The legacy rows were subsequently migrated as described below. No reindex was run.

Metadata migration (2026-11-11): `python src/migrate_filing_metadata.py` dry-run matched all 56 indexed accessions against SEC submissions (1,079 proposed updates; zero unresolved). After checking that the only project Python process was the VS Code formatter, `python src/migrate_filing_metadata.py --write --backup chroma_db_backup_2026-11-11_pre_metadata` made and validated a SQLite-online-backup plus copied HNSW files before updating any records. The backup stays local and is git-ignored. All 1,079 original IDs, documents, and embedding byte hashes matched after migration; every existing metadata key was preserved and only `report_period_end` and `filing_url` were added. Chroma metadata filtering found CMG, JNJ, and XOM for report period 2024-06-30, 13 CMG chunks for that date, and zero results for absent period 1990-01-01. These are metadata-only checks, not semantic retrieval or answer evaluation; no embedding, reranker, NLI, or LLM inference ran. Do not copy HNSW files while another writer is active; the script verifies a copied index but does not enforce an exclusive writer lock. Preserve the backup until the operator accepts the migration.

Migration references: [SEC EDGAR submissions API](https://www.sec.gov/search-filings/edgar-application-programming-interfaces) for accession/reportDate/primaryDocument; [Chroma collection operations](https://cookbook.chromadb.dev/core/collections/) for metadata-only `update`; [Chroma backup guidance](https://cookbook.chromadb.dev/strategies/backup/) for consistency cautions. No forum post or paper was used to assert migration safety: those do not supersede the API contract and direct before/after index verification. Independent review of NLI labels and end-to-end retrieval remains open.

## What the current system actually checks

| Stage | Observed behavior | What remains unproved |
| --- | --- | --- |
| Index | `src/build_index.py` extracts MD&A, chunks it, and stores ticker, accession, form, filing date, and URL for newly built rows. | Whether old rows retain a usable link, reporting-period end, table structure, or original-file fidelity. |
| Retrieval | `src/retrieval.py` merges dense and lexical candidates, optionally reranks, and filters to the earliest filing date within 120 days of a single date in a question. | Whether that filing covers the requested period or every company in the question. |
| Generation | `src/rag.py` sends retrieved text to the LLM and requests structured claims, source indexes, and quotations. | Whether every statement in `answer` is represented by a claim. |
| Quote check | `src/verifier.py` checks normalized quote text occurs in the cited indexed passage. | Whether the claim follows from that quote or whether the indexed passage matches the original SEC document. |
| NLI | When enabled, `src/rag.py` checks structured claims against their cited passages and logs a warning if more than half are unsupported. | Financial arithmetic, coverage of other evidence, or whether an NLI warning blocks an unsupported answer. It does not block the answer. |
| Surface | `app.py` shows `Quote matched in retrieved text` when structured claims exist and have no quote errors. `src/api.py` returns `quote_matched` for structured claims. | Source review, causal correctness, period correctness, and whether all answer prose is claim-covered. |

## Observed risks in priority order

1. **Evidence provenance and scope (pre-migration).** The initial inspection returned 1,079 chunks across seven tickers. All lacked `filing_url` and `report_period_end`; these are now populated as described above. The SEC documents that a filing's accession is a unique submission identifier and provides original documents under accession directories. Use the original filing as the review authority, not the index alone. [SEC EDGAR access guide](https://www.sec.gov/search-filings/edgar-search-assistance/accessing-edgar-data).
2. **Cross-company evidence loss in the previous filter.** A read-only reproduction gave `_filter_to_report_filing()` CMG filed 2024-07-25 and DRI filed 2024-07-26 for a June 30, 2024 cross-company question. It returned only CMG. That selection is fixed per ticker in the current code, with regression tests. The migrated rows now have period-end metadata; an end-to-end cross-company evaluation remains open.
3. **A quote-match is not a claim-verification gate.** `validate_answer()` checks string membership, not entailment. `src/rag.py` returns the generated answer even when NLI warns of unsupported claims, and `app.py` does not show NLI verdicts. `answer` is a separate string from the structured `claims`, with no observed completeness check linking all answer statements to claims. The UI's quote label is literally accurate but can be mistaken for a verified finding. [FActScore](https://arxiv.org/abs/2305.14251) motivates atomic-fact checks for mixed-quality responses; it does not validate this app's decomposition.
4. **NLI is not calibrated for SEC evidence.** On 16 unreviewed, agent-drafted cases from five tickers and four sectors, the installed model accepted four non-supported claims when given full indexed passages. It rejected five supported claims when given short evidence summaries. The two shapes cannot be compared as a product accuracy estimate. The model card describes general NLI datasets, not financial table arithmetic or SEC causality. See [local evaluation](nli-evaluation.md) and the [model card](https://huggingface.co/MoritzLaurer/DeBERTa-v3-large-mnli-fever-anli-ling-wanli).
5. **Three-way evidence semantics are missing from the product.** `aggregate_verdicts()` counts every non-supported prediction together and fails only when over half are unsupported. A refuted number, missing cause, or model error can thus look the same in the warning, and one bad claim can coexist with an overall pass. [FEVER](https://aclanthology.org/N18-1074/) distinguishes supported, refuted, and not enough information with evidence annotations. This is a model for an evaluation contract, not a drop-in replacement classifier.

## Work in verifiable units

1. **Source review before scoring.** Build a case record with exact SEC URL, accession, form, reporting-period end, indexed chunk ID, exact original span, claim, three-way label, rationale, reviewer, and review date. Check extraction against the original filing, including table headings and units. An independent reviewer should resolve ambiguous labels. Do not train or tune on the 16 draft cases as if they were ground truth.
2. **Separate coverage and correctness measurements.** Label whether the relevant filing exists in the index, whether retrieval found the required span, whether generation covered the question, whether quoted text matched the original filing, and whether each atomic numerical and causal claim was supported. Report abstention and unanswered questions as well as wrong answers.
3. **Freeze development and untouched holdout sets.** Include cross-company requests, fiscal-year mismatches, date ambiguity, missing filings, multi-passage evidence, contradictions, tables with quarter and year-to-date columns, and causality not stated by management. Balance cases across the four sectors rather than filling the set with near-duplicates of CMG labor costs. Publish sample counts and labels with each report; do not publish a reliability percentage from the draft set.
4. **Compare candidate systems on the development set.** Test the current citation-only check, cited passage, relevant evidence windows, full retrieved set, and an explicit abstention option. Treat arithmetic and period checks as separate measured capabilities. Compare false accepts, false rejects, refutations mistaken for missing evidence, retrieval misses, and latency. Change runtime policy only after this comparison; evaluate the frozen choice on the holdout once.
5. **Review the user-visible contract.** A failure or uncertainty must be visible in Streamlit and API output, not only in a server log. Keep `quote_matched` separate from independently reviewed factual support. Do not advertise verified findings before the SEC-source review and end-to-end checks pass.

## Sources and limits

- [SEC access guide](https://www.sec.gov/search-filings/edgar-search-assistance/accessing-edgar-data) documents EDGAR originals, accession directories, and fair-use limits. The [original Chipotle Q2 2024 Form 10-Q](https://www.sec.gov/Archives/edgar/data/1058090/000105809024000032/cmg-20240630.htm) is reachable; this audit did not compare every indexed case with its original filing.
- [FEVER](https://aclanthology.org/N18-1074/), [FActScore](https://arxiv.org/abs/2305.14251), and [RAGTruth](https://arxiv.org/abs/2401.00396) are primary research sources for evidence labels, atomic factuality, and RAG hallucination risks. Their published results do not establish this prototype's accuracy.
- The web search integration returned HTTP 402 during this session. No forum consensus was verified; do not substitute unsourced forum advice for filing and code evidence.
- SEC accession directory indexes identified primary document filenames for the five distinct sources in `data/nli_claim_eval.json`. The dataset now records their filing URLs. Python access to the original filing returned HTTP 403 without a configured `SEC_USER_AGENT`. The source text and the draft labels have **not** been independently checked against those originals. Configure a real contact User-Agent before programmatic SEC requests, following the SEC access guide; do not use an invented identity.
- After the operator supplied a real `SEC_USER_AGENT` privately, `src/review_nli_sources.py` fetched the five original filing documents and compared sampled eight-token windows to the indexed passages. See [NLI evaluation](nli-evaluation.md) for counts and limits. Relevant financial paragraphs were located in the originals, but no independent human review or full-filing check of not-enough-info labels has occurred.
