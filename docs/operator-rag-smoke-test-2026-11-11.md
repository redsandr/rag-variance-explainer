## Next decisions and release checks

1. **Retrieval first:** Build deterministic retrieval-only regressions for two tickers/two distinct report dates, one ticker/one date, absent period, and ambiguous/no ticker. Check per-company and per-period coverage *before* reranking/top-k truncation. Do not guess a ticker/date mapping when question semantics are ambiguous; return a clarification or missing-evidence state. Check whether two independent filtered queries per (ticker, period) or another constrained plan is justified by broader examples, not just CMG-JNJ.
2. **Quote mismatch:** Capture the structured model output in a redacted test fixture (without secrets or unapproved personal data). Test citation index, quote text, candidate passages, and whether a quote is unique across sources. Preserve fail-closed behavior; distinguish incorrectly numbered but otherwise exact quotes from invented ones. Never relabel a citation automatically just to make one response pass.
3. **Financial claims:** Review displayed answer vs structured claims and log the exact statement-to-quote mapping. Add human-reviewed cases for nested causal components, percentage-point differences, arithmetic, conflicting periods, and unsupported causal claims across companies. Do not calibrate an NLI threshold against the current 16 agent-drafted cases.
4. **Speed:** Record comparable server runs with effective GPU offload/VRAM, prompt size, decode token count, cache state, concurrent workload and per-run completion timings; no cause for CMG-2's ~6 t/s is established from its four progressive lines alone. The user runs any model inference.

## Research checked for decisions (not proof of this app's correctness)

- [Chroma filtering documentation](https://cookbook.chromadb.dev/core/filters/) documents `where` filters in `Collection.query` and `Collection.get`, including metadata conjunctions. This supports investigating per-company/per-period filtering; it does **not** prescribe how to parse a multi-company question.
- [FEVER (Thorne et al., 2018)](https://aclanthology.org/N18-1074/) defines supported/refuted/not-enough-info evidence annotations; its Wikipedia benchmark is not a financial-domain validation of this NLI model.
- [FActScore (Min et al., 2023)](https://arxiv.org/abs/2305.14251) motivates atomic-fact evaluation and highlights mixed supported/unsupported content; its biography results do not transfer to SEC analysis.
- Primary originals for spot checks: [CMG Q2 2024 10-Q](https://www.sec.gov/Archives/edgar/data/1058090/000105809024000032/cmg-20240630.htm), [WMT 2026 10-Q](https://www.sec.gov/Archives/edgar/data/104169/000010416926000102/wmt-20260430.htm), [JNJ 2026 10-Q](https://www.sec.gov/Archives/edgar/data/200406/000020040626000087/jnj-20260329.htm). Displayed quotations were checked in the earlier provenance review; no complete independent human label review has been done.
- Forum search was attempted and returned HTTP 402. **No forum discussion was verified or used as evidence.** Before choosing a disputed implementation, revisit specific upstream issue/discussion URLs and verify relevance; forum anecdotes are not a replacement for reproducible tests and primary APIs.

## Retrieval follow-up after initial push

The initial record above was pushed as commit `fbc6297`. A deterministic test reproduced the CMG-only retrieval from one globally ranked candidate set. `src/retrieval.py` now plans separate searches only when **at least two indexed companies are explicitly named**: one shared explicit date applies to both, while distinct dates require a one-to-one ordering signaled by “respectively.” Each scoped search filters ticker and reporting-period end at Chroma dense retrieval, filters BM25 candidates to that period, and reserves final result slots per company; if one requested scope has no evidence, return no evidence rather than a one-company comparison. Ambiguous mappings of distinct dates return no evidence. Unscoped and one-company paths retain their prior behavior. This is intentionally limited: it does not interpret all possible natural-language company/period references, infer a financial metric from the operator's underspecified CMG-JNJ question, or prove answer quality.

The installed Chroma index contains 13 CMG chunks for 2024-06-30 and 17 JNJ chunks for 2026-03-29 (metadata-only `collection.get`, no model call). Unit and mocked retrieval tests cover the explicit two-company plan, ambiguous mapping, missing company, and pre-ranking metadata filter. A real-index `query_multi` check substituted a **stored** CMG embedding for `embed_query`, disabled cross-encoder, and lowered min relevance to -1: its five results were CMG chunks 6, 7, 3 and JNJ chunks 10, 9, all in the requested periods. This tests actual Chroma filters and the retrieval path **without AI inference**; it does not measure semantic ranking with a newly embedded question or model reranking. The operator alone runs the subsequent full end-to-end check. [Official Chroma metadata-filtering documentation](https://docs.trychroma.com/docs/querying-collections/metadata-filtering) specifies `where` on `get` and `query`, including `$and`; [IRCoT](https://arxiv.org/abs/2212.10509) is research motivation for directed retrieval in multi-step questions, **not** validation of this implementation. A verified upstream [Chroma issue #1394](https://github.com/chroma-core/chroma/issues/1394) reports slow metadata filtering on 40k documents with Chroma 0.4.17, and [issue #7092](https://github.com/chroma-core/chroma/issues/7092) reopens performance concerns; neither proves a performance regression on our ~1k-chunk installed index. Measure latency in operator runs instead of assuming it. The general web search integration returned HTTP 402, but these specific upstream GitHub issue records were retrieved from GitHub's API.
