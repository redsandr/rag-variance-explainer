## Overview

Phase 2 adds semantic claim verification via Natural Language Inference (NLI) on top of Phase 1's structured output. Instead of only checking verbatim quotes, NLI checks whether each atomic claim is *semantically entailed* by the source chunks.

## Architecture

```
Structured answer (Phase 1)
  → decompose_claims() — LLM-based atomic claim decomposition
    → verify_claims_nli() — MoritzLaurer/DeBERTa-v3-large on GPU
      → aggregate_verdicts() — pass/fail at >50% unsupported
        → nli_verdicts + nli_summary attached to response
```

## Files

### `src/nli.py` (NEW)
| Component | Detail |
|-----------|--------|
| `NLIClient` class | Wraps DeBERTa-v3-large via `sentence-transformers.CrossEncoder` |

| `unload()` | Release model + GC collect |
| Model | `MoritzLaurer/DeBERTa-v3-large-mnli-fever-anli-ling-wanli` (~1.5GB) — ANLI SOTA +8.3% |
| Threshold | Default 0.40 (configurable via `RAG_NLI_THRESHOLD`) |

| Label mapping | Dynamic from `model.config.id2label` — supports any CrossEncoder-compatible NLI model |
| Supported logic | `best_label == "entailment" AND max_entailment >= threshold` — prevents false positives from contradiction/neutral with high entailment scores |

## NLI Optimization (22 Jul 2026)

### Model Swap: `cross-encoder/nli-deberta-v3-large` → `MoritzLaurer/DeBERTa-v3-large-...`

| Aspect | Before | After |
|--------|--------|-------|
| Training data | SNLI + MNLI (550k pairs) | MNLI + FEVER + ANLI + LingNLI + WANLI (885k pairs) |
| ANLI accuracy | baseline | **70.2%** (+8.3% SOTA) |
| Label mapping | Hardcoded `(con, ent, neu)` | Dynamic from `model.config.id2label` |

### GPU Acceleration
- `RAG_NLI_DEVICE=cuda` → inference on RTX 5060
- DeBERTa-v3-large FP16: ~860MB VRAM
- Total VRAM (Qwen 4.7GB + NLI 0.86GB): **5.6GB / 8GB** ✅
- Latency: ~110ms/claim (CPU) → **~30ms/claim (GPU)**

### Supported Logic Fix
`supported = best_label == "entailment" AND max_entailment >= threshold`

Prevents false positives where model predicts contradiction/neutral but entailment score exceeds threshold (common with models that distribute probability mass across multiple classes).

## Pipeline Test Results (CMG Q3 2024 — wrong answer $25.7B)

| Model | Claim 1 | Claim 2 | Overall |
|-------|---------|---------|---------|
| `cross-encoder/nli-deberta-v3-large` (CPU) | neutral, entail=0.095 ❌ | neutral, entail=0.178 ❌ | **FAIL** ✅ |
| `MoritzLaurer/DeBERTa-v3-...` (GPU) | **contradiction**, sup=False ✅ | **contradiction**, sup=False ✅ | **FAIL** ✅ |

MoritzLaurer correctly identifies company mismatch as **contradiction** (stronger signal), while old model only gave neutral.

## Risk Register

| Risk | Impact | Mitigation |
|------|--------|------------|
| Model download 1.5GB in CI | CI timeout/failure | `RAG_NLI_ENABLED=false` + omission from coverage |
| GPU VRAM contention (Qwen + NLI) | OOM on 8GB card | DeBERTa FP16 ~860MB, total 5.6GB/8GB ✅ tested safe |
| False positives (good claims rejected) | Unnecessary fallbacks | Conservative >50% threshold for overall verdict; `supported` only when label=entailment |
| LLM decomposition cost | Extra LLM call per answer | Temperature=0.0, max_tokens=500, cheap generation |
| Label mapping mismatch | Wrong verdicts | Dynamic `id2label` read from model config — supports any CrossEncoder model |
